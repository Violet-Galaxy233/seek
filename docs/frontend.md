# 微信小程序前端方案

## 交互定位

前端采用“自然描述 + 视觉候选网格 + 轻量主动追问”。它不是传统筛选器，也不是满屏聊天气泡。专辑封面是识别答案最快的介质，应成为界面主角。

工作名：`寻迹 Seek`

主文案：`还记得一点，就能找到。`

## 核心流程

```text
描述记忆
→ 查看 AI 理解的线索
→ 浏览候选封面
→ 排除或回答一个问题
→ 候选重新排序
→ 确认专辑
→ 在曲目列表确认歌曲
```

## 页面结构

### 1. 首页

- 多行自然语言输入框。
- 示例：“日语摇滚，封面有很多黑色小皮鞋，背景颜色可能记错了”。
- `封面 / 曲风 / 语言 / 年代 / 人声 / 场景` 六个可选提示标签。
- 主按钮“开始寻找”。
- 提示“不确定也没关系，记错也可以”。
- 不在首页展示完整流派树或高级筛选器。

### 2. 线索确认

短暂展示解析结果：

```text
[鞋子 · 很确定]
[很多只 · 可能]
[红色背景 · 不确定]
[日语 · 可能]
[摇滚 · 可能]
```

三种视觉状态对应置信度。用户可以点标签修改为“很确定 / 好像是 / 可能记错 / 删除”，但不强制逐项确认。明确说明“这些是线索，不会成为硬性限制”。

### 3. 候选结果

- 手机每行两张正方形封面。
- 首屏 4–6 张，懒加载至最多 20 张。
- 卡片展示封面、专辑名、艺人和最多两个匹配标签。
- 不在卡片上展示原始余弦小数或十几个元数据字段。
- 页面顶部说明最关键和可能错误的线索。
- 固定操作：“这些都不像”和“回答一个问题，继续缩小范围”。

### 4. 候选详情

使用底部弹层展示：

- 大封面、专辑、艺人、年份、地区、语言和曲风。
- 匹配线索和冲突线索。
- “不是这张”和“就是这张”。
- 示例解释：“背景并不是红色，但你认为颜色可能记错，因此系统没有排除它。”

### 5. 主动追问

问题作为结果页底部卡片出现，一次只问一个：

```text
你记得封面上有没有人的腿或袜子？

[有] [没有] [不确定]
```

- 回答后原地重新排序，不跳进聊天页面。
- 显示“根据你的回答，候选已重新排序”。
- 保持滚动位置，支持撤销。
- 可解释“为什么问这个：它最能区分当前候选”。

### 6. 找到结果

- 展示专辑和曲目列表。
- 用户选择“找到那首歌了”或“专辑对了，歌曲还没找到”。
- 展示“最初记忆 vs 实际信息”，突出系统处理错误记忆的能力。
- 可生成不含受限封面或已获授权的分享卡片。

### 7. 最近找回

参赛 MVP 使用本地缓存保存最近确认结果，不需要账号和跨设备同步。

## 空结果和失败

空结果文案：`不是你记错了，也可能是我们还没有收录。`

提供：

- 再补充一点记忆
- 放宽颜色和年代
- 提交未收录记忆

区分模型繁忙、网络失败、没有候选、数据未收录和封面加载失败。不得只显示统一的“出错了”。

## 前端状态机

```text
EMPTY
COMPOSING
PARSING
SEARCHING
RESULTS
ASKING
RERANKING
FOUND
NO_RESULT
ERROR
```

所有异步按钮需要防重复提交；离开页面和回退后应恢复当前搜索会话。

## 视觉系统

- 背景：暖白 `#F6F5F1`
- 主文字：墨黑 `#171717`
- 次文字：`#717171`
- 主色：蓝紫 `#665CF6`
- 冲突提示：低饱和橙色
- 使用系统字体和 WeUI 基础控件
- 页面左右边距 16px，组件间距采用 8/12/16/24px
- 封面保持 1:1，圆角 12–16px，轻阴影
- 触摸区域至少约 44px
- 排序和弹层动画 180–250ms，并支持系统减少动画设置
- 预留微信右上角胶囊和安全区域

避免大面积渐变、赛博光效、AI 球、机器人头像和内部模型术语。界面首先应像完整产品，而不是技术演示。

## 文案原则

- 不指责用户记错。
- 不把相似度称为正确概率。
- 使用“很像 / 有一些相似 / 主要是封面物体匹配”等自然表达。
- 加载阶段只描述真实动作，不显示假的百分比。
- 明确告诉用户当前状态、下一步和退出方式。

## 技术选择

- 微信小程序原生框架。
- TypeScript。
- WeUI 基础组件。
- 自定义封面卡片、线索标签、问题卡片和骨架屏。
- 当前 Gradio 不嵌入小程序，只保留为后端验证工具。

## 后端协议需求

搜索响应最终需要包含：

- `search_session_id`
- 原始描述与结构化线索
- 候选及其分组发行版本
- 自然语言匹配和冲突解释
- 下一问题和三态选项
- 数据、模型和索引版本

回答问题、排除候选、确认专辑和确认曲目分别使用明确接口，前端不自行重算分数。
