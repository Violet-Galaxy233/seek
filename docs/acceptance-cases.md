# 30 个真实验收案例设计

## 目的

验收集必须验证“在部分线索记错时仍能找到目标”，而不是验证模型会不会复述专辑标题。案例应来自真实回忆或由不了解系统实现的人根据看过的封面写下，目标答案必须存在于冻结的数据快照中。

30 条只是比赛 MVP 的最小基准。数据和模型比较必须使用同一快照、同一 Top K 和同一评分脚本。

## 每条案例的字段

```json
{
  "case_id": "C01",
  "raw_memory": "红底，好像有一只小皮鞋，日语摇滚",
  "target_release_group_id": "...",
  "target_release_id": "...",
  "clues": [
    {
      "type": "cover_object",
      "value": "shoe",
      "polarity": "positive",
      "confidence": 0.9,
      "truth": "partially_correct"
    }
  ],
  "expected": {
    "initial_top_k": 20,
    "max_questions": 3,
    "final_top_k": 5
  },
  "provenance": "真实用户回忆/受试者描述/专项对抗构造",
  "notes": "颜色和数量错误，并与另一张封面混合"
}
```

`truth` 只用于离线分析，不提供给搜索系统。它可取 `correct`、`wrong`、`partially_correct` 或 `unknown`。

## 案例分组

### A. 准确但模糊的封面记忆：C01–C05

五条覆盖不同视觉类型：具体物体、人物、建筑、风景和抽象图形。描述不出现专辑名、艺人名和歌词。

示例：

- C01：许多鞋子散落在封面上，颜色记不清。
- C02：一个人站在大片空旷场景里，整体偏冷色。
- C03：像水泥建筑或楼梯，几乎没有鲜艳颜色。
- C04：白色花朵，留白很多。
- C05：圆形或月亮一样的主体，深蓝背景。

### B. 关键视觉细节记错：C06–C10

每条至少包含一个强但错误的线索：颜色、物体数量、人物性别、方向或背景场景。用于验证软约束不会把正确答案直接过滤掉。

- C06：红底的一只鞋，实际为非红底、多只鞋。
- C07：记得两个人，实际只有一人或人物为剪影。
- C08：记得夜景，实际只是深色抽象背景。
- C09：记得有文字，实际主封面无明显文字。
- C10：记得物体在中央，实际分散在四周。

### C. 两张封面混合成一次记忆：C11–C14

为每条指定目标封面和“污染来源”封面，原始描述同时包含两者的特征。

- C11：使用《健全な社会》与《Underlight & Aftertime》的真实混合记忆。
- C12：目标的人物加上另一张封面的主色。
- C13：目标的构图加上另一张封面的物体。
- C14：目标封面记忆与同一艺人的另一张发行混合。

### D. 元数据与跨属性记忆：C15–C19

验证视觉之外的召回；至少两条故意混淆艺人地区、发行国家、标题文字和演唱语言。

- C15：中国艺人，英文演唱，封面有城市夜景。
- C16：日本发行，但艺人并非日本人。
- C17：日文标题，主要为纯音乐。
- C18：乐队名称记不清，只记得是三人或四人组合及大致年代。
- C19：只记得女声、英语、爵士或灵魂乐，以及封面主色。

### E. 曲风、年代和情境不确定：C20–C23

描述使用普通人的语言，不直接使用数据库标签。

- C20：“像摇滚但很安静、没有人唱”，目标可能标注为后摇/纯音乐。
- C21：“老一点的电子乐，像在游戏里听过”，年代范围故意偏移。
- C22：“流行歌但吉他很多”，验证多标签而非互斥曲风。
- C23：“咖啡店听到的女声爵士”，情境仅作低权重线索。

### F. 曲名、专辑与发行版本歧义：C24–C26

- C24：用户要找的是一首歌，但只记得它所在专辑的封面。
- C25：同一专辑有多个地区版本和不同封面，任一正确版本应归并展示。
- C26：单曲、EP 与专辑同名，系统需要清楚标记发行类型。

### G. 无答案与数据边界：C27–C28

- C27：目标不在当前数据库，系统不得假装确定，应该说明覆盖不足并建议补充线索。
- C28：描述过于泛化，例如“黑色封面、摇滚”，系统应展示低置信度和高信息增益问题。

### H. 追问有效性：C29–C30

- C29：初始目标在第 6–20 名；一次真实回答后进入前 5。
- C30：用户连续回答“不确定”；系统不应惩罚候选或重复询问相同属性。

## 数据采集方法

1. 选定冻结的专辑快照，随机抽取不同覆盖单元的目标。
2. 让受试者只看封面 10–20 秒，一天后用自然中文描述；不要给字段提示。
3. 记录原话，不要为方便模型而润色。
4. 再询问曲风、语言、年代等记忆，并记录“不知道”。
5. 由第二人核对目标和错误线索，标记 `truth`。
6. 案例入库后不得依据模型失败随意改写；需要修订时保留版本。

## 判定指标

最低报告以下指标：

- `Recall@20`：目标是否出现在第一次返回的 20 个发行组内。
- `MRR@20`：正确目标首次出现位置的倒数均值。
- `Post-question Recall@5`：最多三次追问后是否进入前 5。
- `Question gain`：回答前后正确目标名次和候选熵的变化。
- `Wrong-clue robustness`：B、C 组相对 A 组的召回下降。
- `Coverage abstention`：C27 是否诚实表达未知，而非给出高置信错误答案。
- `Latency`：冷启动、热启动、首次检索和追问重排耗时分别记录。

## MVP 通过线

在首个冻结的 30 条基准上建议采用：

- 初次 `Recall@20 ≥ 80%`。
- 最多三次追问后 `Recall@5 ≥ 70%`。
- B、C 组不得因单个错误颜色或数量线索将目标硬过滤。
- C27 必须触发低置信或库外提示。
- C30 的“不确定”回答不得实质改变候选得分。
- 所有结果均有匹配线索与冲突线索说明。

这些数值是第一版工程门槛，不是最终产品承诺。数据规模扩大后应按覆盖单元分别报告，不能只看总平均值。
