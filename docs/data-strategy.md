# 数据策略

## 目标

长期目标是尽可能覆盖全球、多语言、多曲风音乐，但“覆盖”不能只用总数量衡量。数据集必须同时保证广度、质量、版权来源、可追溯性和长尾代表性。

## 规模路线

| 阶段 | 建议规模 | 目的 |
| --- | ---: | --- |
| 当前原型 | 366 | 验证模型、索引和真实查询 |
| 均衡试验集 | 10,000 | 验证新数据模型和覆盖矩阵 |
| 大赛版本 | 50,000–100,000 | 展示跨曲风和跨语言能力 |
| 产品扩展 | 300,000–500,000 | 提升实际找到率和长尾覆盖 |
| 长期目标 | 1,000,000+ | 全球音乐记忆检索 |

## 覆盖矩阵

每次数据构建都应输出以下维度的分布和缺口：

```text
曲风 × 地区 × 演唱语言 × 年代 × 流行度分层 × 发行类型
```

约束原则：

- 一级曲风和重要二级曲风设最低样本数。
- 欧美、英语和流行内容不得自然占满目录。
- 亚洲、非洲、拉丁美洲、传统音乐和小语种需要单独配额。
- 各年代均应覆盖，避免数字发行集中在近十年。
- 对单个艺人的发行组设置阶段性上限。
- 保留冷门内容，不能只按热度导入。
- Album、EP、Single、Soundtrack 分类统计。

## 流派模型

流派采用多标签图谱，不采用只有一个父节点的简单树。每个标签保存：

- 原始名称和规范名称
- 中文、英文和其他语言别名
- 上位风格和相关风格
- 地域或文化关系
- 来源、票数和可信度
- 专辑级或歌曲级适用范围
- 人工标注或 AI 推断

“纯音乐”、男/女声、速度、情绪和主要乐器是独立属性，不作为流派。

## 音乐实体

- Artist：名称、别名、类型、地区和活跃年代。
- ReleaseGroup：抽象专辑、单曲或原声概念。
- Release：具体国家、日期、介质和封面的发行版本。
- Recording：独立录音实体。
- Track：某个发行版本中的具体曲目位置。
- Work：作品及作曲、作词和改编关系。

艺人地区、发行国家、标题语言和演唱语言必须分开。例如“中国乐队唱英语歌并在日本发行”应能被完整表达。

## 封面层级

### 主封面

每个 ReleaseGroup 选择一个代表封面用于第一阶段召回。

### 版本封面

保留具体 Release 的不同地区、豪华版、再版和实体介质封面。搜索结果按 ReleaseGroup 合并，避免同一专辑多个版本占满 Top-20。

### CoverAnalysis

每张图片除向量外保存：

- 主色和颜色占比
- 物体、数量范围和人物
- 人脸、腿、袜子等可追问属性
- OCR 文字和文字方向
- 摄影、插画、拼贴、极简等风格
- 明暗、饱和度和构图
- AI 描述、模型版本和置信度

## 数据来源

### MusicBrainz

- 当前 API 适合小规模验证，并保持约每秒一次请求。
- 大规模导入改用官方数据库转储，不再逐条搜索 API。
- `mbdump.tar.bz2` 核心数据与 `mbdump-derived.tar.bz2` 标签数据许可不同，必须分开记录。
- 保存 MBID，使用艺人 MBID 精确导入，禁止依赖模糊艺人名查询。

参考：

- https://musicbrainz.org/doc/MusicBrainz_Database/Download
- https://musicbrainz.org/doc/About/Data_License
- https://musicbrainz.org/statistics

### Cover Art Archive

- 当前只下载 front-500 用于本地验证。
- 公开可访问不代表自动拥有公开展示或商业使用许可。
- 公开版本必须确定合法展示方案、来源署名和下架机制。
- 不把封面文件直接提交到 Git。

### 其他来源

引入其他音乐服务、开放数据或合作艺人之前必须记录：

- 数据许可和商用限制
- 图片展示与缓存条款
- API 频率和归因要求
- 数据更新时间
- 删除和权利人请求流程

## 批量管线

```text
下载并校验数据转储
→ 导入暂存数据库
→ 规范化实体和别名
→ 过滤发行状态并选择代表封面
→ 精确去重与近似图片去重
→ 建立覆盖矩阵并抽样
→ 下载缩略图
→ 视觉分析和元数据补全
→ 批量生成向量
→ 自动评测和人工抽检
→ 生成不可变数据快照
→ 发布索引和数据库版本
```

## 质量门槛

- 封面必须可解码，记录 SHA-256 和感知哈希。
- 专辑、艺人、发行版和曲目关系必须完整。
- 不能把未知字段写成否定值。
- AI 推断值与来源事实分开存储。
- 随机抽检和高风险类别抽检均通过后才能发布。
- 每个快照生成规模、重复率、缺失率、流派/地区/语言分布报告。

## 向量规模

2048 维 float32 每个向量约 8 KiB；十万张约 0.8 GB，百万张约 7.6 GB，不含索引额外开销。大规模阶段可用 float16、MRL 截断或 FAISS IVF/PQ 做第一轮召回，Top-N 再用完整向量和结构化证据重排。

## 当前限制

- 366 张数据通过多种 MusicBrainz 标签和艺人文本查询形成，不是可重复的生产快照。
- 模糊艺人查询曾产生同名误匹配，已清理 14 条明显结果，但仍需整体数据审计。
- 当前数据库缺少完整 Artist、Genre、Recording、Work、来源许可和视觉分析表。
- 在这些问题解决前，不继续盲目扩大现有 SQLite 数据库。
